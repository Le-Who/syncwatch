# Palette's Journal
## 2024-05-18 - Dialog Accessibility and Focus State Standardization\n**Learning:** When using custom headless or animated UI layers (like framer-motion `motion.div`) for modal dialogs, they natively lack semantic structure for screen readers, meaning they are completely invisible or un-navigable to assistive technologies. Additionally, relying solely on hover states for interactive elements (like icon-only close buttons) is insufficient; explicitly defining focus-visible styles (`focus-visible:ring-2`) is required for visual keyboard navigation.\n**Action:** Always add `role="dialog"`, `aria-modal="true"`, and `aria-labelledby` attributes to custom modal containers. Apply `aria-hidden="true"` to cinematic background overlays to prevent screen reader confusion. Use existing design tokens (`ring-theme-accent outline-none focus-visible:ring-2`) to provide a universal and visible focus state for all interactive buttons and inputs.
