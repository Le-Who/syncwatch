## 2025-02-27 - [Fix IP Spoofing via X-Forwarded-For Bypass]
**Vulnerability:** The application unsafely parsed the `x-forwarded-for` header when `TRUST_PROXY` was enabled by unconditionally trusting the very first (leftmost) IP in the comma-separated list (`forwardedFor?.split(",", 1)[0]`). Attackers could trivially bypass rate limits by spoofing their IP, achieved by appending fake IPs to the `X-Forwarded-For` header of their request before it reached the trusted reverse proxy.
**Learning:** In a reverse proxy setup, proxies append the client's IP to the end (right) of the `X-Forwarded-For` header. Any IPs appearing before the proxy-appended ones are completely untrustworthy because they are supplied by the client. Always parse this header from right to left, skipping trusted proxy IPs and internal/bogon addresses, until the first public unicast IP is found.
**Prevention:** Always use libraries like `ipaddr.js` to parse from right to left, checking `parsed.range() === 'unicast'` to ignore internal bogon spaces. Never blindly `split(',')[0]` headers controlled or influenced by external clients.
