## 2023-10-27 - [Fix rate-limit bypass via spoofed x-forwarded-for headers]
**Vulnerability:** IP address could be spoofed in API routes and websocket connections by setting arbitrary `x-forwarded-for` headers, which bypassed rate limits and IP checks.
**Learning:** Checking headers directly via `request.headers.get("x-forwarded-for")` is insecure as attackers can control this header on unverified proxies. Node environments often pass multiple comma-separated IPs. Furthermore, prioritizing connection addresses (`socket.remoteAddress`) over proxy headers *behind* a reverse proxy will inadvertently rate-limit the proxy itself, causing a DoS.
**Prevention:** Always use the centralized `getClientIp` function in `lib/ip.ts` that safely extracts the client IP. It parses the comma-separated `x-forwarded-for` list from right to left (most trusted to least trusted), skipping bogon/private IPs, to determine the most accurate remote client IP without causing a DoS on the load balancer, falling back to connection addresses if no proxy header exists.
