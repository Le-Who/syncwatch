## 2025-02-20 - Prevent IP Spoofing via Right-Most X-Forwarded-For IP Extraction
**Vulnerability:** Client IP spoofing was possible because the rate limiter and IP extraction utilities (`getClientIp` and `getAppRouteClientIp`) blindly trusted the first (left-most) IP address in the `X-Forwarded-For` header. Malicious clients could send a fake `X-Forwarded-For` header, and since the proxy appends the real IP to the end of the list, parsing the left-most IP would read the attacker's spoofed IP, allowing them to bypass rate limits.
**Learning:** When behind a trusted proxy, the proxy appends the true client IP to the right-hand side of the `X-Forwarded-For` header string. The left-most parts of the header are easily controlled by the client and cannot be trusted for security or rate limiting purposes.
**Prevention:** Always extract the right-most IP address (e.g., using `forwardedFor?.split(",").pop()?.trim()`) from the `X-Forwarded-For` header when reading it behind a trusted proxy to ensure the true client IP is used and to prevent spoofing.
