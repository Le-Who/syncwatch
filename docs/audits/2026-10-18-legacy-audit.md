## Tooling and dependency corrections

- `clean` now runs a portable Node script that removes only `.next`. A temporary-fixture test verifies source preservation and repeated execution. The previous `next clean` is absent from the supported [Next CLI commands](https://nextjs.org/docs/app/api-reference/cli/next).
- `prune` became `check:unused`, avoiding collision with pnpm's built-in prune command. Knip now includes hooks, root source, tests, and actual framework/server entries. CSS-imported Tailwind is retained explicitly.
- `.prettierignore` excludes generated output, reports, scratch checkouts, and caches.
- `socket.io-client` moved from development to runtime dependencies; the build uses the declared local TypeScript compiler directly.
- Subprocess regression deadlines now account for cold Windows/coverage startup while remaining bounded. Local server tests explicitly disable inherited cloud credentials. Optional real-service suites report skipped tests instead of returning success without executing assertions.
- Browser readiness now waits for the room route, rather than only an open TCP port. Reselection tests preserve the existing saved-position contract and explicitly prove replacement of the old provider DOM node and subsequent seeking; application selection behavior was preserved.

The baseline dependency audit reported **18 high and 14 moderate advisories**. Compatible patches reduced this to **one development-only high advisory**; `pnpm audit --prod` reports zero known vulnerabilities. Patched families include Vitest/coverage 4.1.12, Vite 8.3.4, sharp 0.35.5, source-map-js 1.2.2, brace-expansion 5.0.12, both picomatch majors, smol-toml, YAML/js-yaml, flatted, and @humanfs/node. Major versions of application dependencies were preserved. Native sharp loading/PNG encoding was exercised after installation. The sharp and Vitest patch floors were checked against [the sharp advisory](https://github.com/lovell/sharp/security/advisories/GHSA-wq5f-xc86-pv6w) and [the Vitest advisory](https://github.com/vitest-dev/vitest/security/advisories/GHSA-82fw-gwwq-j7x9).

Remaining dependency conditions:

- `braces@3.0.3` is pulled by development tooling. [GHSA-vfj7-8cjw-p6xm](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm) has no published patched release as of this audit. It was not suppressed or replaced with an incompatible fork.
- `yt-search → cheerio → encoding-sniffer@0.2.1` still pulls deprecated `whatwg-encoding@3.1.1`. No direct dependency is marked deprecated. Forcing encoding-sniffer 1.x outside the parent's declared range would require separate compatibility work; the active YouTube search dependency was retained.
- Vite reports a future native-config-loader compatibility warning for the existing CommonJS-scoped `vitest.config.ts`. The installed configuration works and all original config edits were retained.

## Deliberately retained compatibility

Historical SQL migrations remain necessary to build and upgrade databases. Snapshot normalization, old Redis event envelopes, the old command-envelope adapter, and buffering no-op input still have persistence/protocol consumers. Service-worker cleanup still serves deployed clients with old workers. UUID v5 preserves the mapping of human room IDs to durable UUIDs. Tailwind is imported by CSS, and RoomSocketService has dynamic test consumers. Deployment metadata/ignore files were retained because external tools consume them without imports.

Knip's remaining export/type warnings do not imply dead implementations: room mutation functions participate in the live dispatcher, and some exported classes/interfaces have dynamic or test consumers. No warning was resolved by deleting working behavior blindly.
